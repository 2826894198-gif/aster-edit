# Native checkout layout repair — 2026-10-14

The October 9 release completed direct entry into one checkout but left the approved payment-choice layout disconnected. The owner rejected the remaining Express PayPal / Pay Later duplication, Fastlane email Continue step and oversized heading/mail notice on the real commerce domain. This revision connects the approved layout to the existing WooCommerce and official PayPal Payments integration.

The native classic checkout replaces the Blocks page content at the same `/checkout/` URL. Contact/delivery fields are on the left; exact SKU summary, shipping/total and one payment-choice region are grouped on the right. Mobile reflows into one column. The page uses the full 1200px frame, a compact heading and mail notice, consistent 48px form controls and square Aster actions. The normal form retains native Woo nonces, validation, shipping updates and checkout submission. Order-pay and order-received templates remain outside the layout adapter.

Official Advanced Card fields own card number, expiry and CVV. Ordinary Woo placeholder inputs are hidden and replaced by PayPal hosted components. PayPal has one official action for the selected method; the duplicate Express locations and Pay Later/Venmo buttons are removed from this checkout. Fastlane is disabled through its existing official setting. Wallet choices remain under the provider's eligibility controls; unvalidated Apple Pay is not advertised and unavailable Google Pay stays hidden. No provider/plugin source, credential, webhook, capture or order-status implementation was rewritten.

The owning adapter is in the separate `aster-commerce` repository: `wordpress/mu-plugins/aster-refined-checkout.php` with its CSS/JS and a narrow `woo-shell.php` change. Review used a private native page and explicit review URL before publication, with Woo order submission and provider order writes blocked. Normal checkout was unaffected by review. A regression check preserves the native `%%endpoint%%` AJAX placeholder while appending review context; encoding that placeholder had caused a loading overlay during QA and was corrected before release. Layout specificity also preserves the official wallet hiding styles.

Local adapter checks passed 15/15 without HTTP payment requests. Existing handoff/single-checkout checks passed 12/12. The real browser verifies one checkout form, functioning card/PayPal selection, three official hosted fields, no Fastlane/Express duplicate, unchanged native cart amount and no persistent loading overlay. Matching desktop, 390px and 320px before/after captures are under `qa/checkout-repair-20261014/`. Viewport and document widths agree. Card components were scrolled into view for visual inspection because full-page screenshots can omit an unpainted provider frame below the viewport.

Publication uses `.codex-tmp/checkout-repair-20261014/publish-checkout.php`, after rendered QA. The server keeps exact prior page content and the two affected settings in a restricted serialized backup under `<PRIVATE_DEPLOYMENT_PATH>`. The script verifies unchanged credential/payment, guest, currency, tax, mail and checkout-gate fingerprints. It changes page 7 to `[woocommerce_checkout]`, saves the scoped official styling/Fastlane settings and enables the adapter last. The targeted rollback verifies later changes before restoring the prior page/options and adapter files. It never restores an order/customer/payment database.

No order, authorization, capture or real payment is part of this verification. Provider popup cancellation, 3DS, wallet authorization, webhook reconciliation and matching PayPal capture/Woo paid status still require a merchant-executed transaction. A rendered button or hosted field is not evidence of successful payment collection.

Official references consulted: [PayPal Payments with Woo Blocks](https://woocommerce.com/document/woocommerce-paypal-payments/woocommerce-blocks/) and [PayPal Payments settings](https://woocommerce.com/document/woocommerce-paypal-payments/plugin-settings-guide/), plus the actual installed official version 4.1.3 source for SDK v6 and hosted-card ownership.
