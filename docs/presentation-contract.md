# Aster 交易页面视觉契约

## 已登录账户补充（2026-09-28）

账户总览现用 Woo 客户的订单、地址和资料状态组织为四个明确模块，桌面采用侧边导航与内容区，窄屏将导航重排为可完整触达的网格。订单空态、地址卡和资料表单保持同一白色画布、Cormorant / Inter 字体与细分隔线；在 320/390px 及桌面浏览器完成布局检查。结算关闭时不提供失效的付款方式操作，已登录账户与结算页面禁用共享缓存。功能入口仍指向 Woo 原生订单、地址和资料端点。

2026-09-22 用户明确要求：客户可见页面复用现有 Aster 前端 UI/UX，不接受独立的新设计。展示与交易代码/数据库/发布隔离，不等于品牌体验割裂。

## 当前实现

账户流程最新纠正：注册采用邮箱 + 密码、原生 Woo 创建后直接登录，不要求顾客跳转邮箱设置密码后返回。登录、注册、密码恢复每屏只显示一个表单。历史游客订单仍需证明邮箱所有权才能关联；游客查单邮件流程没有在这次注册修改中变更。已浏览器检查桌面和 390/320px 注册页、手机登录页，未出现横向溢出；注册字段与按钮全宽对齐，保留原生隐私提示和安全处理。

最新背景要求：所有交易页面区域统一纯白 #ffffff，包括页头、主体、表单、手机菜单及页脚。下文的暖白/原始页脚描述仅代表前端参考来源，已被这一明确修正覆盖；按钮与正文保持深色以保证可读性。

- 以现有前端 `src/styles/tokens.css`、`src/styles/aster.css` 的当前 editorial 覆盖规则及 `src/aster/Shared.jsx` 为只读设计来源；并在 `http://localhost:5173/` 实际查看页面，不使用旧 Cute 规范。
- 复用 Cormorant Garamond / Inter、暖白和炭色、细边框、方形主按钮、63px 桌面 / 58px 手机页头、大写字标及导航层级。
- 本仓库 `presentation.php` / `commerce.css` / `woo-shell.php` 为独立的展示适配层，覆盖查单、账户、忘记密码、购物车和原生结账外观。
- 桌面查单使用左右分栏，手机优先表单；原先辅助提示移出手机首屏的主流程，链接有效期仍在表单下说明，账户仍可从页头和页脚进入。
- 账户桌面两列表单使用全部有效内容宽度，手机顺序堆叠。原生 Woo 购物车/结账仍使用 Checkout Blocks 的布局切换、校验和交互，不替换付款按钮处理器。
- 不复制暂不可用的搜索/社交/订阅控件，不伪造帮助政策页面。交易页页脚复用品牌表达并只提供有效的购物、账户、查单入口。后续政策页补齐后再接入。

## 独立资源

字体为从既有 @fontsource 依赖一次性复制的 6 个 WOFF2 文件，400/500/600 字重；同时保留 SIL Open Font License。页面仅从交易域加载自己的 CSS/字体，没有前端目录挂载、软链接、脚本导入或跨域字体依赖。

本地返回展示站的普通链接指向 `http://localhost:5173`；正式环境指向 `https://asteredit.com`。返回链接不是共享会话，两个购物袋尚未连接。字体/样式是版本化快照，不会跟着前端文件的每次修改自动变化：前端确认一轮改版后需有意识地同步并验收交易外观，不能运行时直接加载前端整个 CSS。

## 安全与功能边界

- `template_include` 仅替换 Woo 客户页面外壳；保留 WordPress wp_head/wp_footer、Woo the_content、原生 Nonce/表单和 Store API。
- 不对 PayPal iframe 施加自制支付样式，不改金额、订单权限、capture、refund 和 webhook。
- 查单仍同源、禁缓存、无第三方脚本，CSP 仅新增同源 font-src。
- Sandbox 尚未接入，PayPal 按钮、弹窗和付款结果页面的最终视觉与功能均需连接后实测。当前无可用支付方式是隔离环境的预期状态。
- 本次优先处理用户插入的 UI 一致性要求；购物袋交接端点仍未实现，不能把 Woo 原生购物车预览当作已完成前端交接。

## 验收

自动测试覆盖：查单页保持原有 DOM 交互钩子和安全头；账户登录/找回密码 Nonce 与购物车 Block 保留；字体可独立加载且附带许可证。原有环境、商品、查单 HTTP/SMTP 测试全部回归。

浏览器检查桌面布局、手机 390px / 320px、原生账户和真实虚构商品购物车/结账。仅加入 TEST ONLY 商品预览，未提交付款。最终视觉仍可由用户对照 Aster 前端确认。
