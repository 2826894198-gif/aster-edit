## 已接通的流程

1. **账户找回**：Woo 生成、检查和消费密码重置密钥；本地样式统一。已存在与不存在的账户使用同样确认页，加入限流和同源保护。原生保存新密码、旧密码失效、已用链接拒绝均通过真实 HTTP 与 Mailpit 验证。演示账户为 `phase-one-account@aster.test`。
2. **订单找回和认领**：只填结账邮箱即可请求最近最多十笔订单的私密链接，不要求记住订单号。请求响应不泄露是否存在订单，异步任务只携带订单 ID 和邮箱 HMAC。每个链接十五分钟、一次使用；点击明确的打开按钮后换取 HttpOnly 会话。必须同时登录匹配该结账邮箱的账户，才可把已验证的这一笔订单加入账户。不会按注册时填写的未验证邮箱批量关联历史订单。
3. **交易邮件**：保留 Woo 邮件类、事件、商品/金额表和原生重置流程，适配 Aster 模板。包括账户通知、密码重置、待付款、核对中、已付款准备、记录的出货更新、退款；金额、数量、颜色和订单备注来自订单。核对中不催促再次付款，completed 不等于签收，退款不承诺银行到账日期。顾客邮件回复入口为已确认的客服邮箱。所有发件地址和收件人演示均为测试用途。
4. **店主提醒**：原生新单通知，另对 pending / failed 延迟五分钟。发送前重新读取状态和 paid 日期；付款、取消或状态不符时不发送。每个订单/状态使用原子锁去重，失败释放锁，一小时后重试，总计最多三次。Action Scheduler 正在执行时，重试不能用会拒绝自身的 unique 调度。测试覆盖到期前不发、到期发送、重复抑制、失败重试和取消移除队列。提醒不修改支付状态或订单金额，不增加固定音频生产邮件。
5. **购买评价**：已付购买证据、订单归属和具体订单商品项共同校验；非测试订单读取独立 Aster 支付台账，Woo paid 外观不足以获得资格。按商品/颜色或具体器型保存；一个订单商品项只收一次，同内容重试幂等，不同内容重复返回冲突。退款保留原有购买资格。支持一到五星、文字、显示名、最多六张 JPEG/PNG/WebP、明确公开与照片授权。无主动催评自动化。
6. **评价审核与图片**：使用原生 Products → Reviews / Edit Comment；新增购买订单、颜色、评分、授权和私密照片审核区。评价先进入 pending，审核后才出现在 API 和预览中。原图经解码、缩小、重新编码去除原始元数据；私有上传目录拒绝直接访问，公开图片接口在每次访问时复查审核状态，撤销审核立即隐藏图片。无邮箱、地址、订单凭证进入公开评价数据。

测试产品、评价和照片均清楚标记 TEST ONLY。自动测试图片是一块中性色测试图，不是客户实拍，也不是商品证据；没有编造真实顾客评价。原型保留一条已审核的测试记录，其他测试记录保留审核历史。

## 店面接入和布局

杯页的评价区在商品事实、护理和购买疑问之后。只有 Vite 开发模式且 URL 明确含 `care-preview=1` 时才加载；无已发布评价时整块隐藏。生产构建不包含该测试模块、测试请求或样例评价数据。首页没有增加评价。

第二批预览沿用白底、Cormorant/Inter、细线和方形操作。单条评价自适应占用整行，避免空出半列；评价文字与图片分布协调。表单先用一个紧凑说明行，再并列组织评价内容与姓名/照片/授权，手机按顺序单列。邮箱找回采用相邻、相关的账户与订单任务分组。邮件正文按窄屏调整表格与缩略图，预览框随正文高度伸展。

## 隔离和来源

`aster_phase_two_preview=yes` 仅在 local 且第一批开启时注册功能。代码、资产引用和来源哈希在 `wordpress/mu-plugins/aster-phase-two/`。参考 JWK 的未付款提醒、购买评价、私密评价图片机制；原生邮件头来自当前 Woo 模板。独立命名空间、数据库、订单、顾客和支付配置，没有运行时跨项目导入。没有 JWK 经营主体、地址、税号、凭据或支付通道。

本地 SMTP 在最后一个 PHPMailer 配置钩子强制指向容器 `mailpit:1025`，无认证、无 relay、SMTP 端口不对主机开放。Mailpit UI 仅 loopback 暴露。生产邮件门禁没有开放，PayPal 和结账门禁没有放开，未发布任何内容。
