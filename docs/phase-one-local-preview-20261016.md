# Aster 第一批功能本地预览

日期：2026-10-16。依据：店主已审阅的《Aster Edit 功能补全与 SEO 建设方案》第一批。只实现本地预览，没有执行部署或真实支付。

## 入口与范围

- 汇总入口：http://127.0.0.1:8088/aster-preview/
- 顾客查单：http://127.0.0.1:8088/order-status/
- 测试邮箱：`phase-one@aster.test`。六种演示订单的编号在汇总入口可见。
- 原生后台物流编辑：汇总入口的 Edit test shipment in Woo，使用已有本地管理员登录。
- 结账备注：汇总入口的 Preview checkout note。空袋时只添加隐藏测试 SKU；如果原结账袋有别的商品，保留原袋并直接进入该袋的备注预览，不替换商品。

保留白底、Cormorant/Inter、细边框、深色方形操作和独立 Woo 数据。没有共同运营声明、JWK 公司与地址、音频定制或新增支付渠道。既有未发布首页与杯子内容稿没有混入此功能。

## 已实现

1. 订单结果：待付款、失败、确认中、已记录付款、已退款、已取消的服务端状态映射，六个合成订单供预览。付款确认中及已付/退款订单不显示再次付款动作。真实订单读取已有 Aster 支付台账；Woo paid 状态本身不能替代对账。
2. 同单恢复：只在服务端允许时使用原订单的 Woo order-pay URL。没有新建订单或自行重试支付的接口。预览保留关闭的支付门禁，真实授权、capture、退款均未验收。
3. 备注：Woo 原生 `order_comments`，可选折叠，前端 500 字符与字数显示，服务端同样校验。顾客自己的备注进入订单详情；日期和变更需要确认，不形成定制或到货承诺。
4. 客服：按订单号生成主题和邮件草稿，支持支付、物流/地址、破损/错发、其他主题，支持复制和手动选择草稿。Open email 只打开客户邮件应用；本实现不代发邮件。
5. 物流：原生 Woo 订单内录入承运商、运单、可选追踪 URL、已确认的预计到达、最新更新及最多 25 条轨迹。保存经过订单权限与 nonce 校验；输入错误保留旧记录。只保存物流 metadata，不变更金额、订单/付款状态。
6. 展示：账户详情、原生订单结果、游客查询使用同一份订单组件。空物流紧凑显示；查单后使用完整详情宽度。没有真实签收信息时不因 Woo completed 声称 Delivered。

汇总入口的状态卡片直接展示明确标记的合成订单，避免查看演示时触发 Woo 原生 thankyou 的清空购物车行为。真实原生结果和账户路径仍保留 Woo 权限/订单 key/邮箱核验，另有 HTTP 检查。

## 隔离与兼容

`aster_phase_one_preview=yes` 只在 `wp_get_environment_type() === local` 时注册功能。PHP、JS、CSS、素材和适配来源位于 `wordpress/mu-plugins/aster-phase-one/`；原始 JWK 参考文件哈希在 `source.json`。照片是批准的 Olive 实拍衍生图的原样副本，没有重新生成或编辑商品。

原查单 API 默认字段保持不变。新界面通过 `X-Aster-Order-View: detail` 请求经过访问校验的、已转义的详情 HTML；不返回邮箱、地址、订单 key 或付款链接。原同源、限流、no-store、no-referrer、邮件短效访问规则保留。新预览的图像 CSP 只允许本服务及明确的本地 Aster 图片来源，其余默认拒绝策略保留。查单资料不进入 localStorage。

本地继续阻止 Live PayPal，最终付款按钮禁用，正式结账门禁继续关闭。自动邮件仍只进入容器 Mailpit；没有对外发信，也没有添加邮件系统。物流同步指各页面读取同一记录，不是自动抓取承运商或购买面单。

## 关闭本批预览

在本仓库执行 `docker compose run --rm cli option update aster_phase_one_preview no`。它只关闭本批展示与录入，不恢复或删除数据库，也不覆盖订单。定向修改前的原查单文件保存在 `.codex-tmp/phase-one-before-20261016/`；无需恢复它们即可停用预览。合成订单和隐藏测试商品保留供复核。

真实支付验收、认证发件通道、评价、多币种和 SEO 发布均不在本批完成声明内。
