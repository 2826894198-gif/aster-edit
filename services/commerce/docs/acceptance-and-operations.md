# 验收与运行手册

区分 `计划`、`本地验证通过`、`Sandbox 验证通过`、`生产验证通过`。安装插件、模拟支付或收到 mock webhook 均不能算真实 Sandbox 付款通过。

## 测试矩阵

| 层 | 验收场景 | 必须保留的证据 |
| --- | --- | --- |
| 隔离 | 前端文件未改、独立 Git/卷/端口/密钥；数据库无公开端口 | diff、compose、服务状态 |
| 客户 | 游客、注册、登录、忘记密码、账户归属、地址快照 | 虚构记录与邮件箱结果 |
| 查询 | 正确/错误邮箱、重复/过期链接、他人订单、限流、日志脱敏 | 请求/响应和访问控制测试 |
| 商品 | 不可售、非法购物数量、未知 SKU、改价、单品或套装组件从有货切换为缺货 | 服务端金额、商品状态与错误结果 |
| 结账 | 运费变化、地址校验、重复提交、刷新/关闭/返回、会话过期 | 浏览器与订单记录一致 |
| PayPal | 正常 capture、买家取消、拒绝、超时、资金 pending | PayPal Sandbox 订单/交易 ID、金额/币种、Woo 订单 |
| 异步事件 | 真签名/伪签名、重复、乱序、迟到、丢失后对账 | webhook 结果、库存和通知次数 |
| 退款 | 部分/全额、重复操作、远端成功但本地超时 | PayPal refund ID、累计金额和 Woo 退款 |
| 履约 | 未付不能发货、分包、追踪号、破损和取消请求 | 角色权限、包裹记录与邮件 |
| 邮件 | 下单、付款、发货、退款、恢复密码、失败重试 | 测试邮箱与队列，不仅 wp_mail 返回值 |
| 运维 | 重启后恢复、备份恢复、版本回滚、cron积压、插件升级 | 恢复演练及告警记录 |
| 前端接入 | 320/390/桌面、键盘、跨域、Safari、窄屏错误提示 | 交接到原生结账的真实截图和浏览器结果 |

## 环境推进

1. 本地：虚构数据、邮件只进 Mailpit、无 Live 通道；跑基础验证。
2. 预发布：独立域名/数据库、Sandbox 商户和买家；HTTPS 443 webhook 可达，外部访问受控但不挡回调。
3. 正式：核实销售主体/地区/币种、SKU价格库存、运税与政策、发信域名；独立 Live 接入；完成约定的上线验收。

开发容器不能直接拿来覆盖现有服务器。当前发现远端已有 MySQL/Redis和额外监听服务；先明确服务归属、网络边界和备份，再建立专属站点/数据库。数据库监听情况仅说明需检查，并不证明外网可达。

## 运行要求（生产前必须实现）

- 独立部署用户；最小文件权限；后台 MFA 与账号分工；禁用文件在线编辑。
- 反向代理明确排除 cart/checkout/my-account、Woo session 与动态 API 缓存；HTTPS 及代理来源可信。
- 真 cron 驱动 Woo 队列；告警针对 webhook 连续失败、待处理付款、退款失败、发信失败、队列积压、磁盘和备份异常。
- 对账任务只查状态；发现差异进入人工工作单，不能自动重新扣款。
- 插件升级先在预发布验证完整矩阵，保存 WordPress/Woo/PayPal 插件和容器摘要。
- 数据库及上传加密备份到独立存储，测试恢复；不把含 PII 的生产数据复制到开发环境。
- 发布回滚代码与配置；恢复旧数据库会丢失新交易，因此必须停写并制定补账方案，不能作为普通回滚步骤。
- 不把 PayPal mock webhook 当作正式验签或付款证据；实际 Sandbox 商户事件单独验收。

## 尚需业务输入

不会阻塞本地基础搭建，但在对应功能验收前需要：

- PayPal 商户注册地区、收款主体、首发结算/显示币种；独立 Sandbox 商户与买家。
- 首发配送国家、仓库发货地、运费和包装重量、库存/缺货规则、定价与税处理。
- 发信域名/服务商、客服邮箱、退款/取消/破损/隐私与条款文本。
- 后台实际使用人员和角色，以及恢复时间和备份保留要求。

凭据只在受控后台或本地密钥文件配置，不要求用户在聊天中发送密码或 Client Secret。
